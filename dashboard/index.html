Research Framework & Execution Specifications

Core problem statement, methodology, execution steps, and evaluated baselines

01

Executive Summary & Objective

Conducts an empirical comparative study between WebAssembly (Wasm) runtimes and standard OCI (Docker) containers. Evaluates lightweight machine learning inference across heterogeneous hardware architectures (x86_64 vs. ARM64).

WasmEdge / Wasmtime OCI Containers x86_64 vs ARM64
02

Problem Statement

While Docker containers are the industry standard for microservices, their resource footprint and startup latency bottleneck low-power edge devices. WebAssembly promises near-native speed and lightweight footprints, but lacks comprehensive cross-architecture benchmarks for AI workloads.

Container Overhead Startup Latency Edge Bottlenecks
03

Proposed Novelty & Methodology

• Built functional REST microservices performing MobileNetV2 image classification in Rust/Wasm (WasmEdge/Wasmtime) and Go/Docker.
• Executed multi-platform benchmarking across x86_64 cloud instances (AWS EC2) and ARM64 edge platforms (Raspberry Pi 4 / AWS Graviton).

MobileNetV2 REST AWS EC2 c6i Raspberry Pi 4
04

Implementation & Execution Steps

  • Step 1: MobileNetV2 inference engine in WebAssembly (Rust/WasmEdge) & Docker (Go/Python).
  • Step 2: Deployed services across local ARM64 (Raspberry Pi/Graviton) & x86_64 testbeds.
  • Step 3: Configured load testing via JMeter/k6 scaling from 100 to 10,000 requests.
  • Step 4: Host telemetry captured using perf, docker stats, and systemd timestamps.
